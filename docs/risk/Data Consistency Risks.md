# Rủi ro nhất quán dữ liệu giữa các service

| Giai đoạn | Thời điểm có thể lệch dữ liệu | Hậu quả |
| --- | --- | --- |
| **1. Đăng ký tài khoản: User Service → Payment Service** | User Service lưu user/profile trong transaction rồi gọi Payment tạo ví trước khi commit. Payment đã commit tạo ví nhưng response bị timeout, hoặc một bước tiếp theo/commit ở User Service thất bại làm transaction User rollback. | Ví vẫn tồn tại trong Payment nhưng user/profile không tồn tại trong User Service. Chưa có bước tự động đối soát hoặc bù trừ cho ví mồ côi này. |
| **2. Đăng ký làm streamer: User Service → Channel Service** | User Service thêm role `STREAMER`, lưu streamer rồi gọi Channel tạo channel trước khi commit. Channel đã commit nhưng response bị timeout hoặc transaction User thất bại. | Role/streamer bị rollback nhưng channel vẫn tồn tại, tham chiếu đến `streamerId` không tồn tại. Đăng ký lại có thể tạo streamer với ID khác, trong khi channel cũ chưa được xử lý. |
| **3. Cập nhật tên/avatar: User Service → Channel Service** | User Service sửa profile, upload avatar mới nếu có, rồi gọi cập nhật channel trước khi commit profile. Channel đã cập nhật nhưng User nhận timeout hoặc transaction profile rollback. | Profile giữ tên/avatar cũ nhưng channel giữ tên/avatar mới. Khi rollback, cleanup có thể xóa avatar mới trên R2 trong khi channel vẫn giữ URL đó, làm ảnh channel không truy cập được. |
| **4. Tạo stream: Stream Service → MediaMTX** | Stream Service tạo session trong transaction rồi gọi MediaMTX tạo path. MediaMTX đã tạo path nhưng response bị timeout, process crash trước commit hoặc transaction Stream rollback. | Path tồn tại trên MediaMTX trong khi session không tồn tại trong DB. Chưa có đối soát tự động để dọn path mồ côi trong phạm vi MVP. |
| **5. Kết thúc stream/hết hạn reconnect: Stream Service → MediaMTX** | MediaMTX đã đóng/xóa path nhưng một bước kiểm tra tiếp theo lỗi, process crash trước commit hoặc transaction cập nhật session không commit. | Media đã đóng nhưng DB vẫn có thể giữ trạng thái `LIVE` hoặc `RECONNECTING`. Metadata và trạng thái phát thực tế không khớp cho đến khi có xử lý tiếp theo thành công. |
| **6. Callback online/offline: MediaMTX → Stream Service** | Nguồn phát thay đổi trạng thái nhưng callback bị mất hoặc xử lý thất bại và không có lần gửi lại thành công. MVP chưa có cơ chế đối soát tự động để phát hiện trạng thái bị bỏ sót. | Nguồn đã online nhưng session vẫn `READY`, hoặc nguồn đã offline nhưng session vẫn `LIVE`. Luồng xem và xử lý reconnect có thể dựa trên trạng thái DB không còn đúng với media. |
| **7. Trả kết quả thumbnail: Media Worker → Stream Service** | Worker đã upload ảnh lên R2 nhưng crash trước callback, hoặc callback thất bại trước khi Stream Service commit kết quả. Job worker hiện cấu hình `attempts: 1`. | Ảnh tồn tại trên R2 nhưng DB chưa ghi nhận thumbnail mới. Job có thể hết hạn thành `FAILED`, còn ảnh trở thành dữ liệu mồ côi. Cơ chế gửi lại job chưa nhận ACK và chống callback trùng/cũ hiện có không bảo đảm phục hồi bước trả kết quả này. |
| **8. Yêu cầu gửi OTP: User Service → Kafka → Notification Service** | Trong luồng xác thực email hoặc quên mật khẩu, User Service đã lưu OTP/cooldown vào Redis nhưng process crash trước khi publish Kafka. Xử lý exception hiện có không bao phủ được crash giữa hai bước. | OTP/cooldown tồn tại nhưng Notification không nhận được yêu cầu gửi email. Người dùng chưa nhận được OTP và có thể phải chờ cooldown hết trước khi yêu cầu lại. |
