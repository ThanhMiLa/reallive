# Write repository issues

Use the title format `[Service Name] Main issue summary`. When multiple services are primarily responsible for the work, list them inside the same brackets, separated by commas: `[Service Name 1, Service Name 2] Main issue summary`. Include only the main responsible services, not every service related to the feature.

The body contains only a `### Description` section. Briefly explain the purpose and expected behavior of the feature, or describe the problem, how it occurs, and what needs fixing. Keep the description at a high level; omit detailed technical design and implementation instructions unless the user explicitly requests them.

Use the labels requested by the user and preserve existing labels when editing unless asked to change them. Creating or editing an issue requires the user's instruction to do so; a request for a draft alone does not authorize publishing it.
